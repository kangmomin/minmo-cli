새 worktree 를 만들 때 `.gitignore` 로 빠진 파일(`.env` 등)을 함께 가져옵니다.

## 바뀐 점
- **무시된 파일 가져오기**: worktree 를 새로 만들면 git 이 추적하지 않아 빠져 있던 파일을 원본 폴더에서 복사합니다. 새 worktree 에서 바로 실행·테스트할 수 있습니다.
  - **원본**: 로컬 저장소·기준 저장소는 그 저장소 폴더, 그 밖의 GitHub 저장소는 ★기타 worktree, 기타가 없으면 가장 최근에 커밋한 다른 worktree.
  - **빼는 것**: `node_modules`, `target`, `dist`, `build`, `out`, `.next`, `.nuxt`, `.venv`, `venv`, `__pycache__`, `.gradle`, `.turbo`, `.cache`, `coverage` — 크고 다시 만들 수 있는 폴더입니다. 의존성은 지금처럼 생성 후 스크립트(`npm ci` 등)로 설치하세요.
  - **순서**: [로컬 파일] 에 보관해 둔 파일 → 무시된 파일 → 생성 후 스크립트. 스크립트가 가져온 `.env` 를 쓸 수 있습니다.
- **설정**: 전역·조직·저장소 설정에 **무시된 파일 가져오기** 가 생겼습니다. [가져오기] / [가져오지 않음] 을 고르고, 가져오지 않을 폴더·파일 이름을 한 줄에 하나씩 적습니다.
- CLI(`minmo`)도 같은 방식으로 가져옵니다. 설정 이름은 `ignoredCopyExclude` 입니다(`off` 면 가져오지 않음).

## 알아 둘 점
- **업데이트하면 기본으로 켜집니다.** 끄려면 전역 설정에서 [가져오지 않음] 을 고르세요.
- **제외 목록에 없는 큰 폴더는 그대로 복사됩니다.** 무시해 둔 데이터·캐시 폴더가 있다면 그 이름을 설정에 추가하세요. 이름은 경로 어디에 있든 맞으면 빠집니다(패턴은 쓸 수 없습니다).
- 복사는 worktree 가 열린 뒤에도 이어질 수 있습니다. 파일이 많으면 끝나기 전에 `.env` 가 아직 없을 수 있고, 복사 도중에 멈출 수는 없습니다(복사 중에 worktree 를 삭제하면 복사가 끝난 뒤 지웁니다).
- 이 저장소의 첫 worktree 는 가져올 원본이 없어 건너뜁니다(GitHub 저장소). 먼저 ★기타 worktree 에 `.env` 등을 두면 그 뒤로 만드는 worktree 가 가져갑니다.
- **새 브랜치에서도 무시되는 파일만** 가져옵니다. 원본 브랜치의 `.gitignore` 에만 있고 새 브랜치에는 없는 규칙의 파일은, 새 worktree 에서 커밋 대상으로 보이지 않도록 가져오지 않습니다.
- 통째로 무시된 폴더를 가져올 때도 그 안의 제외 이름(`node_modules` 등)과 중첩 저장소의 `.git` 은 빼고 가져옵니다.
- "가장 최근 worktree" 는 마지막 커밋 시각으로 고릅니다. 원하는 원본이 따로 있다면 ★기타 worktree 에 두는 것이 확실합니다.
- 이미 있는 파일은 덮어쓰지 않습니다. [로컬 파일] 에 보관해 둔 파일이 먼저 들어가므로 그쪽이 우선합니다.
- 심볼릭 링크와 링크를 지나는 경로는 복사하지 않습니다(`.env` 가 링크라면 오지 않습니다). 복사에 실패한 파일이 있어도 나머지는 복사하고 이슈는 열리며, 준비 기록에 사유가 남습니다.
- 이름에 `\`·줄바꿈·따옴표 같은 특수 문자가 든 무시된 파일은 가져오지 않습니다.
- 이미 만든 worktree 에는 적용되지 않습니다(새로 만들 때 한 번).
- 제외 목록은 PC 사이 동기화 대상이 아닙니다.
- 설치 파일에 코드 서명이 없어 SmartScreen 경고가 뜰 수 있습니다.
