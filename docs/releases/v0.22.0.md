worktree 경로를 원본 폴더 기준으로 적을 수 있습니다. 이슈 머리줄에서 이슈를 고치고 닫을 수 있습니다. 원격 CLI 는 데스크탑 서버와 연결하는 명령만 남기고 줄였습니다.

## 바뀐 점
- **worktree 경로를 원본 기준으로 적기**: 설정의 worktree 경로를 다음 중 하나로 시작합니다.
  - `./` `../`: 원본 폴더 기준 상대 경로. 예: 원본 `/src/app` 에서 `../app-wt/{branch}` → `/src/app-wt/<branch>`
  - `~`: 홈(전과 같음)
  - `/`: 절대 경로. Windows 에서는 원본이 있는 드라이브의 루트입니다. 예: 원본 `D:\src\app` 에서 `/wt/x` → `D:\wt\x`
  - "원본"은 메인 clone 폴더입니다. 기준 저장소와 로컬 저장소는 그 폴더입니다.
  - 원본 위치가 기기마다 달라도 같은 설정을 함께 씁니다.
  - 트리의 "경로 변경됨" 배지와 설정 미리보기도 같은 규칙으로 계산합니다.
- **이슈 머리줄에서 수정·닫기**:
  - **GitHub 이슈**: 제목·본문을 고칩니다. 이유(완료 · 계획 없음)를 골라 닫습니다. 닫힌 이슈에는 [닫힘] 배지가 붙습니다.
  - **로컬 작업**: 제목을 고치고 바로 닫습니다.
  - 바꾼 항목만 GitHub 에 보냅니다. 다른 곳에서 고친 내용을 덮어쓰지 않습니다.
- **원격 CLI 를 줄였습니다**: 데스크탑 서버와 연결하는 명령만 남깁니다.
  - 남은 명령: `login` `logout` `doctor` `update` `sessions` `note` `config` `repos`
  - 없앤 것: TUI(`minmo` 만 입력), `ls` `new` `open` `rm`, 로컬 모드(`mode`), `terminal`, `base-dir` `base-repo`, `repos reset`
  - worktree · 터미널 · 이슈 등록은 데스크탑(원격 호스트 포함)에서 합니다.
  - `minmo doctor` 는 역터널 소켓 · 서버 응답 · 로그인만 점검합니다.

## 알아 둘 점
- 원본 폴더 안이나 원본을 품는 상위 폴더에는 worktree 를 만들지 않습니다(오류).
- `./` `../` 로 시작할 때만 원본 기준입니다. `.worktrees/...` 처럼 점으로 시작하는 폴더 이름은 오류입니다.
- 메인 clone 경로에는 원본 기준 경로를 쓸 수 없습니다(`~` 또는 절대 경로만).
- 기준 저장소들이 같은 상위 폴더에 있으면 `../{branch}` 는 저장소끼리 겹칩니다. 원본 기준 경로에는 `{repo}` 를 넣으세요.
- 이슈를 닫아도 worktree 는 그대로입니다.
- github.com 에서 바꾼 제목은 머리줄에 바로 보이지 않습니다.
- 원격 CLI 에서 `minmo` 만 입력하면 도움말을 보입니다. 없앤 명령은 `unknown command` 로 알립니다.
- 로컬 모드였던 원격 기기는 서버 모드로 동작합니다. SSH 역터널로 접속한 뒤 `minmo login <코드>` 로 로그인하세요. 남은 `~/.config/minmo/config.json` · `state.json` 은 지워도 됩니다.
- 이전 CLI 로 만든 원격 worktree 는 그대로 남습니다. 데스크탑의 원격 호스트 기능으로 다룹니다.
- 원격 CLI 는 `minmo update` 로 업데이트합니다.
- 설치 파일에 코드 서명이 없어 SmartScreen 경고가 뜰 수 있습니다.
