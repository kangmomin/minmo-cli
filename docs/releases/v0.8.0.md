새 프로젝트를 앱에서 시작하고, 이미 있는 저장소 폴더를 열어 관리할 수 있습니다. GitHub 저장소가 아니어도 됩니다.

## 바뀐 점
- **저장소 추가(+) 메뉴**: 사이드바의 **+** 버튼에 세 가지가 있습니다.
  - **새 프로젝트**: 이름과 위치를 정하면 폴더를 만들어 git 저장소로 시작합니다(빈 첫 커밋 포함). GitHub 저장소는 만들지 않습니다.
  - **폴더 열기**: 이미 있는 저장소 폴더를 엽니다. origin 이 GitHub 저장소면 그 저장소의 이슈와 함께 열리고(폴더는 기준 저장소로 쓰입니다), 아니면 로컬 저장소로 열립니다. 이 PC 에서는 폴더 선택 창으로 고를 수 있습니다.
  - **GitHub 저장소 추가**: 내 계정·내 조직 소유가 아니어서 목록에 없던 저장소(협업 중인 저장소·공개 저장소)를 `owner/name` 으로 더합니다.
- **로컬 저장소와 작업**: GitHub 저장소가 아닌 폴더(origin 없음, GitLab 등)는 트리의 **로컬 저장소** 아래에 보입니다. 이슈 대신 앱 안에서 만드는 **작업**(제목 → 번호 1, 2, 3…)을 쓰며, 작업마다 브랜치·작업 폴더·터미널·파일·커밋·메모를 이슈와 똑같이 씁니다. 작업은 우클릭 메뉴에서 닫고 다시 엽니다.
- **GitHub 에 올리기**: origin 이 없는 로컬 저장소의 메뉴에서 소유자·이름·공개 여부를 정하면, GitHub 저장소를 만들어 모든 브랜치를 push 하고 트리 항목을 GitHub 저장소로 바꿉니다. 작업은 같은 번호의 이슈가 되고 메모·프로젝트 설정도 옮겨집니다. 중간에 실패하면 같은 메뉴에서 이어서 진행합니다.
- 원격 호스트를 보고 있을 때는 새 프로젝트·폴더 열기가 그 호스트에서 이뤄집니다(경로는 직접 입력).

## 알아 둘 점
- 로컬 저장소와 작업 목록은 이 PC 의 앱에 저장됩니다. 다른 PC 와 공유되지 않으며, **목록에서 제거** 하면 작업 목록(번호·제목)은 사라집니다(폴더·브랜치는 남습니다).
- 로컬 저장소만 쓰더라도 앱 로그인은 지금처럼 GitHub 로그인이 필요합니다.
- 로컬 저장소에는 PR 버튼이 없고, origin 이 없으면 push 버튼도 없습니다. GitHub 가 아닌 origin 의 fetch·push 는 그 PC(호스트)의 git 인증을 씁니다.
- 새 프로젝트의 첫 커밋에는 git 의 `user.name`·`user.email` 설정이 필요합니다.
- "GitHub 에 올리기" 의 push 는 이 PC 에서는 git 에 설정된 GitHub 인증을, 원격 호스트에서는 이 PC 의 GitHub 토큰을 씁니다. 올린 뒤 기존 작업 폴더에는 "경로 변경됨" 이 표시될 수 있습니다(폴더는 옮기지 않습니다).
- `~/.ssh/config` 의 별칭을 호스트로 쓴 origin 주소(`git@별칭:owner/repo`)는 GitHub 저장소로 알아보지 못해 로컬 저장소로 열립니다.
- 설치 파일에 코드 서명이 없어 SmartScreen 경고가 뜰 수 있습니다.
