이슈에서 바로 코딩 에이전트를 실행할 수 있습니다.

## 바뀐 점
- **에이전트 실행**: 이슈 머리줄의 **[에이전트 실행]** 버튼, 또는 트리에서 이슈를 오른쪽 클릭 → **에이전트 실행…** 으로 엽니다.
  - 에이전트(Claude Code · Codex · Gemini CLI · 직접 입력한 명령)를 고르고 지시문을 적으면, 그 이슈의 작업 폴더에서 새 터미널 패널을 열어 실행합니다.
  - 지시문에는 이슈 번호·제목(GitHub 이슈면 주소도)이 미리 채워집니다. 비워 두면 에이전트만 띄웁니다.
  - 실행하기 전에 터미널에 들어갈 명령을 그대로 보여 줍니다.
  - 에이전트별 명령은 고칠 수 있고(예: 옵션 추가), 고친 명령과 마지막으로 고른 에이전트는 이 PC 에 저장됩니다. `{prompt}` 자리에 지시문이 들어갑니다.
- 쓰고 있는 터미널에는 명령을 끼워 넣지 않습니다. 이미 터미널이 떠 있으면 그 오른쪽에 새 패널을 만듭니다.
- 원격 호스트의 이슈에서도 같은 방식으로 실행합니다.

## 알아 둘 점
- minmo 는 명령을 터미널에 입력해 줄 뿐입니다. 실행한 뒤의 진행은 에이전트 현황(상태·하위 에이전트·알림)으로 보며, 에이전트의 작업을 대신 판단하거나 자동으로 이어 가지 않습니다.
- 에이전트 CLI 는 그 터미널에서 실행할 수 있게 미리 설치·로그인되어 있어야 합니다(원격 호스트의 이슈는 그 호스트에).
- 지시문은 한 줄로 바뀌어 들어갑니다(줄바꿈은 공백으로).
- 명령의 `{prompt}` 는 따옴표로 감싸지 않습니다(`claude "{prompt}"` ✗ → `claude {prompt}` ✓). 지시문은 자동으로 감싸져 들어가며, 따옴표 안에 두면 실행할 수 없다고 알려 줍니다.
- 지시문을 비우면 `{prompt}` 와 바로 앞의 한 글자 옵션(`-i`, `-p`)만 함께 빠집니다. `--task {prompt}` 처럼 긴 옵션은 그대로 남으니 미리보기를 확인하세요.
- 원격 호스트의 이슈는 항상 새 패널에서 실행합니다. 첫 패널은 앱을 꺼도 남아 있는 tmux 세션에 다시 붙기 때문에, 거기서 돌던 프로그램에 명령이 입력되지 않게 하기 위해서입니다.
- 원격 터미널이 비밀번호나 호스트 키 확인을 묻는 동안에는 명령을 넣지 않고, 셸이 뜬 뒤에 넣습니다. 2분 안에 터미널이 뜨지 않으면 명령은 버려집니다.
- 이 PC(Windows)의 터미널에서는 지시문의 큰따옴표(`"`)가 작은따옴표(`'`)로 바뀝니다. Windows PowerShell 이 큰따옴표가 든 인자를 쪼개 넘기기 때문입니다. 실행 전 미리보기에서 확인할 수 있습니다.
- 직접 입력한 명령이 `.cmd`·`.bat` 파일이면 지시문의 `&`, `%` 같은 글자를 cmd 가 해석할 수 있습니다. 이런 명령에는 지시문을 비우고 터미널에서 직접 입력하세요.
- 설치 파일에 코드 서명이 없어 SmartScreen 경고가 뜰 수 있습니다.
