이슈의 작업 폴더에서 코딩 에이전트 3개를 차례로 돌려 E2E 테스트를 하는 E2E 테스트 큐를 추가했습니다.

## 바뀐 점
- **E2E 테스트 큐** (#92): 이슈를 큐에 넣으면 그 작업 폴더에서 ① E2E 실행 → ② 엣지케이스 찾기 → ③ 엣지케이스 기반 테스트를 터미널 패널로 차례로 실행합니다.
  - 이슈 머리줄의 [E2E 큐에 추가] 로 넣고, 상단 바의 [E2E 큐] 버튼으로 대화상자를 엽니다. 큐는 한 번에 작업 1개만 실행하고 나머지는 추가한 순서대로 기다립니다.
  - 단계마다 그 이슈에 새 터미널 패널을 엽니다. 입력 중인 패널의 포커스는 옮기지 않고, 끝난 단계의 패널은 남깁니다.
  - 에이전트가 결과 파일(`.minmo/e2e/<작업 id>/`)을 쓰고 쉬는 중이면 다음 단계로 넘어갑니다. [다음 단계] 로 먼저 넘길 수도 있습니다. 결과 폴더는 git 변경에 보이지 않습니다.
  - 에이전트가 확인을 기다리거나, 종료됐거나, 결과 파일 없이 쉬고 있으면 상단 버튼에 "확인 필요"가 보입니다.
- **역할 설정** (#92): [E2E 큐] 의 역할 설정 탭에서 단계마다 CLI(Claude Code · Codex · Gemini CLI)·모델·지시문을 정합니다.
  - 세 CLI 의 모델 목록을 불러와 고릅니다. 원격 호스트(SSH)에서도 가져옵니다. 목록에 없으면 이름을 직접 입력합니다.
  - 지시문에는 `{issue}`(이슈)·`{out}`(이 단계 결과 파일)·`{prev}`(앞 단계 결과 파일) 자리를 씁니다. [기본값] 으로 되돌립니다.
  - 설정은 이 PC 에 저장하고 페어링한 다른 PC 와 동기화합니다.

## 알아 둘 점
- 큐는 앱 메모리에만 있습니다. 앱을 다시 시작하면 사라집니다. 창(화면)마다 큐가 따로 있습니다.
- 단계 패널은 터미널 탭이 열려야 뜹니다. 이슈 화면을 하나라도 열어 두세요. 110초 안에 터미널이 뜨지 않으면 그 작업은 실패합니다.
- [취소] 해도 이미 실행 중인 에이전트는 패널에서 계속 돕니다. 패널에서 직접 종료하세요.
- Claude Code 는 모델 목록 명령이 없어 로컬 캐시에서 읽습니다. 캐시가 없으면 `opus`·`sonnet`·`haiku` 만 보입니다.
- 설치 파일에 코드 서명이 없어 SmartScreen 경고가 뜰 수 있습니다.
