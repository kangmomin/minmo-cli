터미널은 이슈를 고를 때가 아니라 **Ctrl+T** 로 열 때 만들고, tmux 는 선택 사항이 됩니다.

## 바뀐 점
- **터미널은 열 때 만듭니다**: 이슈를 고르면 작업 폴더(worktree)만 준비합니다. 터미널(셸)은 만들지 않습니다. 이슈를 잘못 골라도 터미널이 생기지 않습니다.
  - **Ctrl+T**: 터미널이 없으면 시작하고, 이미 있으면 오른쪽에 새 패널을 만듭니다.
  - **[터미널 열기] 버튼**: 터미널이 없는 화면에 나옵니다(휴대폰·브라우저로 붙은 화면용).
  - **[에이전트 실행]** 은 실행할 때 터미널을 시작합니다.
  - 다른 기기가 이미 연 터미널에는 열지 않아도 붙습니다(새 프로세스를 만들지 않습니다).
- **tmux 는 선택 사항입니다**: 터미널의 기본값은 일반 셸입니다.
  - **데스크톱**: **원격 호스트** 대화상자에 **원격 터미널에 tmux 사용** 이 생겼습니다(기본 꺼짐, 이 PC 에 저장). 켜면 tmux 가 있는 호스트의 터미널이 전용 tmux 세션이 되어, 앱을 끄거나 연결이 끊겨도 유지됩니다.
  - **CLI**: `minmo terminal [shell|tmux]` 명령이 생겼습니다(기본 `shell`, 이 기기에만 저장). `shell` 은 worktree 에서 `$SHELL` 을 열고 `exit` 로 돌아옵니다. `tmux` 는 전과 같은 전용 세션(`tmux -L minmo`)을 씁니다. Windows 는 항상 PowerShell 입니다.
  - `minmo doctor` 는 tmux 방식일 때만 tmux 를 점검합니다.
- **에이전트 상태 점 위치**: 사이드바 이슈 행의 에이전트 상태 점이 왼쪽으로 갔습니다. worktree 유무 표시(`●`)는 없앴습니다.

## 알아 둘 점
- **업데이트하면 tmux 가 꺼집니다.** 전에 쓰던 tmux 세션에는 다시 붙지 않습니다. 계속 쓰려면 데스크톱은 [원격 터미널에 tmux 사용] 을 켜고, CLI 는 `minmo terminal tmux` 를 실행하세요. 켜면 전의 세션에 다시 붙습니다.
- tmux 를 끄면 원격 터미널은 앱을 끄거나 연결이 끊길 때 함께 끝납니다.
- tmux 를 끄면 원격 호스트의 Codex 는 에이전트 현황에 나오지 않습니다(Claude Code · Gemini CLI 만 감지합니다).
- tmux 설정은 새로 여는(또는 [다시 시작] 한) 터미널부터 적용됩니다. 실행 중인 터미널은 그대로입니다.
- worktree 를 삭제하면 설정과 상관없이 그 worktree 의 tmux 세션을 정리합니다.
- **셸의 Ctrl+T(글자 맞바꾸기·fzf)는 쓸 수 없습니다.** 앱이 먼저 처리합니다(Ctrl+D · Ctrl+W 와 같은 정책).
- 브라우저로 붙은 원격 화면에서는 브라우저가 Ctrl+T 를 씁니다. [터미널 열기] 버튼을 쓰세요.
- 다른 기기가 방금 연 터미널이 목록에 나오기 전(최대 약 4초)에 [에이전트 실행] 을 하면, 명령이 그 터미널에 들어갈 수 있습니다.
- macOS CLI 의 `shell` 방식은 worktree 를 삭제할 때 백그라운드 프로세스를 정리하지 못합니다.
- 설치 파일에 코드 서명이 없어 SmartScreen 경고가 뜰 수 있습니다.
