## 기능 목표
원격(SSH) 터미널의 연결이 끊기면, minmo가 같은 패널에서 자동으로 다시 접속해야 한다. 다시 접속한 뒤 resume 같은 명령은 사용자가 입력한다.

## 변경 사항 (To-Be)
1. **끊김 판정 (Rust, pty.rs):** 원격 PTY의 ssh가 끝나면 종료 코드를 읽는다.
   - 255 + 출력 끝이 auth·host_key가 아님 → 세션을 지우지 않는다. `pty-exit`를 내지 않는다. 재접속 루프를 시작한다.
   - 255 + auth·host_key → 시도 없이 바로 "실패" 상태.
   - 255가 아님 → 지금과 같음(`pty-exit` → "종료되었습니다 [다시 시작]").
   - (구현 확정) auth·host_key 판정은 그 시도가 **연결 표시를 보기 전**의 255일 때만 한다(`pty_link.rs` `on_exit`). 연결된 뒤의 255는 항상 재시도. 처음 연 터미널도 같다(AC-11).
   - (구현 확정, D-27) 원격 로그인 셸(tmux 끔)이 255로 끝나면 `pty.rs` `login_shell`이 254로 바꿔 넘긴다 — ssh 자체의 실패(255)와 가리기 위해서다. tmux 첫 창의 셸은 `exec`라 해당 없음.
2. **재접속 루프 (Rust):** 기다림 2·4·8·16·30초, 최대 5번. 시도마다 같은 RemotePty·cwd·크기로 새 ssh를 열고 같은 PTY id에 붙인다. 상태 변경마다 이벤트(대기·시도 중·성공·실패, n/5)를 낸다. 이 이벤트는 원격 기기에도 보낸다.
   - (구현 확정) **시도 마감 30초:** 시도(Connecting)가 연결 표시(원격 명령이 맨 앞에 내는 창 제목 `minmo-link`, tmux는 제목 `minmo:`)를 30초 안에 보지 못하면 실패다. ssh와 그 자손(ProxyCommand 등)을 끝내고 다음 기다림으로 간다.
   - (구현 확정) **안전망:** 마감 때 ssh가 살아 있고 화면에 보이는 출력이 있으면(ConPTY 시작 시퀀스·공백만 있는 것은 제외) 연결된 것으로 본다 — 연결 표시를 내지 못하는 원격(ForceCommand, `.bashrc`의 `exec`)과 프롬프트 인증. 이때 시도 횟수는 그대로이고 구분 줄은 없다. 뒤늦게 진짜 표시가 오면 횟수를 0으로 되돌린다.
   - (구현 확정) **Connecting 2초 주기 확인:** 이 PC(Windows)의 ConPTY는 ssh가 끝나도 출력 파이프를 닫지 않아 EOF가 오지 않는다. 그래서 감독이 Connecting·Live에서 2초마다 ssh가 끝났는지 확인하고, 끝났는데 3초 안에 EOF가 없으면 감독이 대신 판정한다. 빨리 실패하는 시도(연결 거부·DNS 실패)도 마감(30초)을 기다리지 않고 다음 기다림으로 넘어간다(AC-02의 간격 유지).
3. **구분 줄:** 성공하면 출력 스트림(지난 출력 보관 포함)에 `── 연결이 끊겨 다시 접속했습니다 (HH:MM) ──` 한 줄을 넣는다. 이전 출력은 지우지 않는다.
   - (구현 확정, D-25) 구분 줄은 **연결 표시로 연결을 알았고 대체 화면이 아닐 때만** 넣는다(tmux 제목으로 알았거나 대체 화면이면 커서 위치를 모른다). 어느 경우든 안내 줄에 `다시 접속했습니다 (HH:MM)`(③)이 3초 보인다 — tmux 켬·끔 공통.
4. **명령:** [지금 재접속] = 기다림을 건너뛰고 바로 시도. [재접속](실패 뒤) = 5번을 처음부터 다시.
   - (구현 확정) 시도 중(Connecting)에는 버튼이 `aria-disabled`라 눌러도 반응이 없고 포커스는 유지된다. 동시에 눌러도 시도는 하나다.
5. **tmux 분할 세션:** `destroy-unattached on`을 쓰지 않는다. 다시 붙을 때 `destroy-unattached off`를 설정한다(이전 버전 세션). 분할 패널을 Ctrl+W로 닫으면 그 `-pN` 세션을 끝낸다.
   - (구현 확정, D-26) 이슈의 첫 패널 id(`first`)를 저장해 기본 세션 역할을 그 패널에 고정한다(`store/ui.ts`, 공유 상태 `store/shared.ts`). 분할·닫기로 바뀌지 않아, 첫 패널을 닫아도 남은 패널은 기본 세션으로 옮겨 가지 않고 자기 `-pN` 세션에 붙는다. 첫 패널의 기본 세션은 패널을 닫아도 끝내지 않는다.
6. **화면 (TerminalTab.tsx):** 재접속 상태 이벤트로 안내 ①②를 보인다. 재접속 중에는 키 입력을 보내지 않고, write 실패를 "종료"로 보지 않는다. 늦게 붙은 화면은 pty_find 응답으로 지금 상태를 받는다.
   - (구현 확정) 안내 ③은 실시간 connecting → connected 전이에서만 3초 보인다(늦게 붙은 화면의 스냅샷으로는 띄우지 않는다). 재접속 이벤트를 받으면 그 패널의 출력을 3초간 에이전트 활동으로 세지 않는다(다시 그리기가 "끝남" 오알림을 내지 않게).
7. **README:** '원격 호스트' tmux 행과 재접속 설명을 고친다.

## 알려진 제한
구현 뒤에도 남는 제한이다(README '연결이 끊기면'에도 사용자에게 의미 있는 것을 적었다).
- 재접속한 새 ConPTY는 이전 화면 내용을 모른다. 창 크기를 바꾸거나 다른 화면이 붙어 ConPTY가 다시 그리면 화면에 보이던 이전 출력·구분 줄이 지워질 수 있다(스크롤백은 남는다).
- 연결 표시를 내지 못하는 원격(ForceCommand, `.bashrc`의 `exec`)은 재접속마다 30초 뒤에야 안전망으로 연결된 것으로 본다. 그 세대의 출력 꼬리가 세션 전체라 사용자 출력의 "Permission denied"를 인증 실패로 오판할 수 있고, 시도 횟수가 0으로 돌아가지 않는다.
- D-26 부작용: 다른 패널을 둔 채 첫 패널을 닫으면 기본 tmux 세션이 보이지 않는 채로 계속 돈다(모든 패널을 닫고 새로 열면 붙는다 — 지금과 같음).
- `rekey`(로컬 저장소 → GitHub 올리기)로 패널 번호가 1부터 다시 시작하면 남은 `-pN`에 새 분할 패널이 붙을 수 있다. 재접속 시도 중 분할 패널을 닫거나 worktree를 지우면(`pty_kill_by_cwd` → KILL_TMUX, EC-04) 진행 중이던 원격 `new-session -A`가 세션을 다시 만들 수 있다(드묾).
- 무작위 지연이 없어 여러 패널이 동시에 재시도하면 sshd `MaxStartups`·fail2ban에 걸릴 수 있다(개인 도구 — 패널 수가 적다).
- 비밀번호·passphrase 인증은 지원하지 않는다(README '준비물'). 재접속 시도 중 입력은 버리고, 30초 안전망으로 연결된 것으로 본 뒤에야 입력이 간다.
- 끊김 감지는 ssh의 `ServerAliveInterval=15` × 3(약 45초, D-02)에 기댄다. 감지 시간 변경은 범위 밖이다.
