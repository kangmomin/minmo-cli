## 기능 목표
여러 에이전트 세션을 한꺼번에 돌릴 때, 지금은 트리에서 저장소 → 이슈 → 터미널을 하나씩 찾아가 답을 넣어야 한다.
상단 바에 **[답변 모드]** 를 더한다. 켜면 프로젝트를 나누지 않고 답을 기다리는 세션을 하나씩 앞에 보이고, 답하면 다음 세션으로 넘어간다. 새 세션은 기본 보기의 프로젝트·이슈 트리 대화상자로 만든다.

## 확정된 추론 (2026-11-27 Plan 승인)
- **A-1 자동 이동 때 포커스(AX-A1)**: 자동으로 이동해도 **새 터미널에 키보드 포커스를 넣지 않는다**(AX-02). 직전 포커스가 터미널 영역(가려지는 옛 터미널 포함)·카드 안에 있었고 도착 때도 그곳(또는 body)에 있으면 **요약 카드 제목**("세션 요약", `tabIndex=-1`)으로 옮긴다. 이어서 치던 글자·Space·Enter 는 아무 데도 가지 않는다. 답하려면 다음 Tab 자리인 **[이 세션에 답하기]** 를 누른다(그 터미널이 키 입력을 받는다).
- **A-2 자동 이동은 "답을 보냄"·"끝남" 두 신호에서만**:
  - 답을 보냄: 지금 세션이 (a) 화면에 보인 동안 기다리는 상태였고, (b) 마지막 기다림이 시작된 뒤 그 패널에 입력이 있었고, (c) 지금 작업 중이고, (d) 작업 중이 되고 0.4초 뒤에는 입력이 없었고(이어서 치는 중이 아님), (e) 마지막 입력 뒤 2초가 지났을 때만 넘어간다(D-02).
  - 끝남(D-13): 화면에 보인 동안 에이전트가 잡혔던 세션에서 (가) 그 패널에 에이전트가 없어졌거나(셸만 남음 — '기타' 프로그램이 돌면 끝난 것으로 보지 않는다) (나) 그 패널을 닫았고(옆 패널이 보임), 끝난 뒤 1초가 지났고, 끝난 뒤 그 패널(보이는 패널)에 입력이 없고, 마지막 입력 뒤 2초가 지났으면 넘어간다. 포커스는 A-1 과 같다.
  - 그 밖에는 자동으로 넘어가지 않는다 — 사용자가 고른 세션·새 세션·Ctrl+T 셸 패널은 [건너뛰기]·목록으로 옮긴다.
  - **입력** = xterm 키 처리기가 PTY 로 보내게 둔 키(편집 키 Ctrl+Backspace·Shift+Enter·IME 조합 키 포함)·붙여넣기·키 줄 입력. 수정 키만(Shift·Control·Alt·Meta·AltGraph·CapsLock) 누른 것과 키 처리기가 PTY 로 보내지 않고 처리한 앱 동작 키(Ctrl+Shift+M, 새 터미널·분할·닫기, 새 창, 글자 크기, 선택 복사)는 입력이 아니다.
- **A-3 기다리는 세션에는 끼어들지 않음**: 지금 세션이 작업 중이 아니면 더 급한 세션이 생겨도 넘어가지 않고 "더 급한 세션 N개 [보기]".
- **A-4 (A-2 로 합침)**: 사용자가 바꾼 화면을 지키는 별도 hold 는 없다 — A-2 의 두 신호가 없으면 자동 이동이 없으므로 사용자가 고른 화면은 그대로 남는다.
- **A-5** 범위 창(#105)에서는 [답변 모드] 버튼을 숨긴다.
- **A-6 보이는 패널만 "보는 중"**: 답변 모드는 에이전트 추적의 "보는 중"을 패널 단위로 바꾼다(기본 보기는 이슈 단위 그대로).

## Jev 계약 (TypeSafe 공식 OpenAPI 요약)
- `POST https://api.typesafe.ai/v1/systemone`, `Authorization: Bearer <key>`, `Content-Type: application/json`.
- 요청 required `model`·`state`·`questions`. Choice: required `type`·`criteria`(object 1~255), `instructions` 선택. Score: required `type`·`criteria`(array 1~10).
- 응답 required `model`·`answers`·`usage`. Choice `{type:'choice', choice, confidence, probabilities}`, Score `{type:'score', score(소수), confidence, legend, probabilities}`. 다른 type → "판정 없음".
- 오류: 400·401·413·415·422·429·529. 긴 문맥 헤더는 쓰지 않는다(약 32KB 이하 — 제3자 문서 값, 미확인).
- 키는 Rust 안에서만 키체인에서 읽어 헤더에 넣는다(웹 화면으로 오지 않음). 원격 화면의 허용 명령에 넣지 않는다.

## 접근성 규칙 (AX-A1~A5)
- **AX-A1 자동 이동 포커스**: 새 터미널에 키보드 포커스를 넣지 않는다. 직전 포커스가 터미널 영역·카드 안이고 도착 때도 그곳(또는 body)이면 카드 제목("세션 요약", `tabIndex=-1`)으로 옮긴다. 카드 제목 다음 Tab 자리는 [이 세션에 답하기] 이고, 이 버튼은 Enter·Space 를 keyup 에서만 누른다(버튼이 직접 받은 반복이 아닌 keydown 의 keyup 에서만 — 누른 채 둔 키의 반복이 새 터미널로 가지 않게). 포인터·보조 기술의 click 은 그대로 동작한다. [건너뛰기]는 포커스를 옮기지 않는다. 터치 키 줄은 포커스가 그 패널 안일 때만 PTY 로 보내고, 밖이면 첫 누름은 그 터미널로 포커스만 옮긴다.
- **AX-A2 포커스 대체 위치**: 보이는 패널이 바뀌면(자동 이동·열기 대기·사용자 선택 어느 쪽이든) 가려진 터미널·[다시 시작]·[재접속]·[터미널 열기]에 포커스가 남지 않는다 — 카드 제목으로 옮긴다. 포커스된 요소가 사라지면(예: 닫힌 대화상자·누른 뒤 사라진 버튼) 카드 제목 → 빈 안내 [새 세션] → 목록 [새 세션] 순서로 첫 번째로 포커스가 가는 곳으로 옮긴다. [새 세션] 대화상자를 닫을 때도 열기 전 자리로 자동 복귀하지 않고 같은 규칙을 쓴다.
- **AX-A3 알림**: 넘어갈 때(자동 이동 적중·[건너뛰기]·[보기]) polite 상태 영역(`role="status"`)에 "다음 세션: {저장소} {이슈} — {상태}" 를 알린다. 같은 글도 다시 읽히게 글을 비운 뒤 다음 frame 에 넣는다. 열 수 없을 때 등 오류는 별도 `role="alert"` 에 알린다. 사용자가 목록에서 직접 고르면 알림을 지운다.
- **AX-A4 aria-disabled**: [건너뛰기]·[이 세션에 답하기]·"열 수 없음" 줄은 `disabled` 대신 `aria-disabled` + 사유 글(`aria-describedby`)을 쓴다(포커스를 잃지 않고 이유를 읽을 수 있게). [이 세션에 답하기]의 사유는 보이는 작은 글로도 둔다.
- **AX-A5 답변 모드 터미널 패널**: 탭 목록이 없다. 터미널 영역은 `tabpanel` 이 아니다(이름 없는 tabpanel·끊긴 `aria-labelledby` 가 없고, Tab 정지점도 아니다). 터미널 입력은 카드 "어디" 줄을 `aria-describedby` 로 함께 읽는다(카드 제목·[이 세션에 답하기]도 같다). 목록 줄의 접근 이름은 1초마다 바뀌지 않는다(지난 시간은 `aria-hidden`).

## 구현 메모 (사용자에게 보이는 동작의 결정·편차)
- 지금 줄이 없어도(셸 패널·새 패널) [이 세션에 답하기]를 둔다(제목에서 Tab → Enter 로 그 터미널에 가는 길을 늘 같게). 터미널이 아직 열리지 않았으면 `aria-disabled` + 사유("터미널을 여는 중입니다"/"터미널이 아직 열리지 않았습니다").
- 카드의 "기다리는 세션 N개"는 지금 세션도 센다(목록 제목 "기다리는 세션 N"과 같은 수).
- 세션 목록 묶음 순서는 기다리는 세션 → 작업 중 → "열 수 없음"(있을 때만, 맨 뒤). 줄이 없는 묶음은 제목만 둔다. 포인터·포커스가 목록 안에 있는 동안은 각 묶음 안의 줄 순서를 고정한다.
- 세션 기록이 없으면 "최근 기록에 답변이 없습니다", 기록 파일을 열거나 읽지 못하면(이 PC) 또는 원격 조회가 실패하면 "답변 기록을 읽지 못했습니다"(EC-10, 품질 리뷰 뒤 고침).
- 원격 Claude 기록은 ssh 연결이 된 뒤에만 읽는다(연결 전·실패면 읽지 않는다). 원격 스크립트가 0 이 아닌 코드로 끝나면 "답변 기록을 읽지 못했습니다".
- 작업 중인 세션도 Claude 마지막 답변을 지연 없이 읽어 보인다 — 작업 구간마다 한 번(다시 작업 중이 되면 앞 구간에 읽은 답을 쓰지 않고 다시 읽는다). 작업 폴더를 모르면 읽지 않고 "최근 기록에 답변이 없습니다". 기록 시각이 기다리기 시작한 때보다 이르면 1.5초 뒤 한 번 더 읽고, 그 뒤에는 읽지 않는다(실패해도 같다).
- Jev API 키 검사(화면·Rust 같음): 앞뒤 공백을 뗀 뒤 비었거나 0x21~0x7E(보이는 ASCII) 밖의 글자(가운데 공백·줄바꿈·한글)가 있으면 저장하지 않는다. 서버 설정 [저장]은 입력한 키가 있으면 서버 설정보다 먼저 키를 저장하고, 잘못된 키·키체인 오류면 닫지 않고 서버 설정도 저장하지 않는다. 취소하고 다시 열면 키 입력 칸은 비어 있다.
- 키 상태는 "키체인: 저장됨/없음/확인 중…/확인하지 못했습니다"로 늘 보인다. 판정 중 키가 없다고 나오면(다른 창에서 지운 경우) 오류 알림 대신 키 안내로 바뀌고 [Jev 판정]은 사라진다. 키 확인이 실패하면 버튼을 보이고, 누르면 오류 문구가 나온다.
- 열 수 없어 이동에 실패하면 "열 수 없습니다: {저장소} {이슈}" 를 알린다. 켜는 순간 진입에서 지금 이슈를 열지 못한 것은 알림 없이 머리줄 오류만 보인다.
- 답변 모드가 아니면 [건너뛰기]·목록 고르기 등은 아무것도 하지 않는다. 다음 기다리는 줄이 없으면 [건너뛰기]는 건너뜀 기록도 남기지 않는다.
- 답변 모드에서는 [변경]·[파일]·[메모]·[이슈] 탭 내용을 그리지 않는다(항상 터미널 탭이라 빈 tabpanel 이 남지 않게).
- Claude 답변 상자의 제목은 "Claude Code 마지막 답변"(+ " · N분 전 기록")이다.

## 한계
- **미검증으로 남는 것**: 실제 Jev 호출(키 없음 — 요청·응답은 공식 OpenAPI 와 mock 으로만 확인), 실제 원격 호스트 ssh 로 Claude 기록 읽기, 원격 화면(브라우저·휴대폰) 실기(화면 키보드·붙은 터미널 크기·브라우저 알림), 다른 창·휴대폰이 연 세션 열기·끝난 PTY·다른 창의 크기 변경(E2E mock 이 공유 터미널·pty-exit·pty-resized 를 내지 않음 — vitest 만), 가려진 xterm 의 WebGL 비용(측정 후 판단), 실제 Codex 의 크기 변경 출력, 새 색 조합 대비(계산으로 확인).
- **자동 이동 한계(A-2)**:
  1. 출력으로 상태를 보는 에이전트(Codex)는 답을 쓰다 멈춘 사이 화면 출력(파일 찾기 등)이 나오면 넘어갈 수 있다.
  2. `/exit` 직후 프로세스 조회(3초) 전 출력이 "작업 중"으로 보이면 '답을 보냄'으로 넘어갈 수 있다. (1)(2) 모두 포커스는 카드 제목으로 가므로 글자는 다른 세션으로 가지 않고, 치던 글은 옛 패널에 남는다.
  3. tmux 를 쓰지 않는 원격 터미널은 제목으로만 판단해, 에이전트가 끝나도 제목이 남으면 끝남 이동이 없다(PTY 가 끝나면 있다).
  4. 답한 뒤 상태가 다시 기다림으로 바뀌면(예: Codex 처럼 출력으로 상태를 보는 에이전트는 4초 조용하면 대기 중이 된다) 새 입력이 있어야 넘어간다. 그래서 "다음이 없어 지금 세션을 유지하다가 나중에 기다리는 세션이 생기면 넘어감"(AC-06)은 지금 세션이 그때까지 작업 중일 때만 된다(그 밖에는 [건너뛰기]).
  5. 목록 줄·트리 줄에서 Enter 를 누른 채로 두면 반복 키가 고른 터미널로 간다(사용자가 고른 이동 — 기존 D-33 과 같음).
  6. 에이전트가 끝나고 프로세스 조회(3초) 전에 셸에서 '기타' 프로그램(개발 서버 등)을 띄우면, 그 프로그램이 끝난 때를 끝난 때로 본다 — 그 사이의 입력(예: Ctrl+C)은 감지 전 입력이라 막지 않아 2초 뒤 넘어간다. 포커스는 카드 제목으로 가므로 글자는 다른 세션으로 가지 않는다.
- 서버 설정을 불러오지 못하면 "세션 요약" 절도 보이지 않는다(기존 구조). 원격 화면에는 서버 설정 버튼이 없어 요약 설정을 바꿀 수 없다(이 PC 에서 바꾼 값을 따른다).
- 'entry'·'skip'·'pick' 이동이 실패하면 출발한 패널로 되돌아가 머문다([건너뛰기]·목록으로 다음). 되돌릴 패널이 없으면 실패한 이슈가 선택된 채 머리줄 오류가 보이고 자동 이동은 없다.
- Claude Code 기록 형식은 공개된 규격이 아니라 버전에 따라 읽지 못할 수 있다(그때는 "읽지 못했습니다"·"답변이 없습니다", 다른 기능은 그대로).
